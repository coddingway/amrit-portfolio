# Portfolio Content Rehual Plan
**Owner:** Amrit Podder  
**Goal:** Replace generic developer portfolio content with a market-grade personal brand that communicates authority, transformation, and value — in the first 10 seconds.

---

## The Core Problem With the Current Site

The current site answers: *"Who is Amrit Podder?"*  
A great portfolio should answer: *"Why Amrit Podder over everyone else?"*

Right now, any recruiter or market leader scanning the site sees:
- Name + title (same as 10,000 other portfolios)
- Generic stats (years, projects, brands — no context)
- Project cards with no business framing
- About text that reads like a LinkedIn summary

There is no **aura**. No narrative. No point of view.

### SECTION 3: The Transformation Story (New Section — After Stats)

This is the section that builds the aura. No other developer on the market has this specific arc in this specific way.

**Primary caption (hero / about section):**
> *From Notepad to AI agents. Still learning.*

**Secondary line (use inside the transformation story body — as a section break or pull quote):**

This second line works best mid-story, right after the early years paragraph, before the AI pivot lands. It acts as a breath — the reader thinks the arc is done, then you hit them with "and everything that came after."

**Section title options:**
- "The Long Game"
- "How I Got Here"
- "8 Years of Getting It Wrong First"

**The actual story — written in Amrit's voice:**

```
I wrote my first line of HTML in Notepad.
Not VS Code. Not Sublime. Notepad.
Windows XP. A monitor the size of a microwave.
No autocomplete. No syntax highlighting. No Stack Overflow.
Just a blank white screen and a blinking cursor.

That's where I started.

I didn't come from a CS background. I studied Chemistry.
I taught myself how the web worked by breaking it constantly
and fixing it slowly. Every tag typed by hand. Every property
looked up in a printed reference guide.

By the time I got my first agency job, I had already learned
the most important thing about frontend development:
the browser doesn't care how you feel about your code.
Either it renders or it doesn't.

Over 8 years I watched the stack change completely.
jQuery became React. Tables became Flexbox became Grid.
WordPress got a block editor nobody asked for.
Shopify went headless. Then everything went headless.
Then everything got an API. Then the APIs got GraphQL.

I kept up. Not because I had to — because I was genuinely
curious about why each change was happening.

Then in 2023, I tried an AI coding tool properly for the first time.
It wrote a component in 40 seconds that would have taken me an hour.

I didn't feel threatened. I felt like I was back in 2015
with Notepad — watching something new arrive and deciding
whether to learn it or ignore it.

I learned it.

The difference between me and a developer who started with AI
is that I know what it got wrong before I run it.
I know the edge case it missed. I know the pattern it's copying
without understanding why the pattern exists.

That's not a flex. That's just what 8 years of doing it
the slow way gives you.

I'm still learning. Every day.
The tools change. The fundamentals don't.
I've rebuilt my workflow three times in the last two years.
I'll probably rebuild it again before this year ends.

That's the job. And I genuinely love it.
```

**Visual format:** Scroll-driven vertical timeline. Each era has a texture shift — early years feel like a terminal/monospace aesthetic, middle years feel like a design tool, present day feels like an AI interface. The progression is visual, not just textual.

## Tone & Voice Guide

| Avoid | Use Instead |
|-------|-------------|
| "Passionate about" | "I care about" (more direct) |
| "Results-driven" | Just show the results |
| "Cutting-edge technologies" | Name the specific technology |
| "Works well in a team" | "Led and mentored 8 developers" |
| "Diverse experience" | List the actual diversity |
| "Problem solver" | Describe a specific problem you solved |

**Voice rule:** Write like a senior who's been around long enough to be direct. No hedging. No buzzwords. Confident, clean, occasionally dry.

**One test:** After writing any copy block, ask: *"Could a junior developer with 2 years of experience also say this?"* If yes — rewrite it to be more specific.

## Case Study — Before / After Format

Every case study page (WorkDetail) where conversion/performance data exists must include a **Before / After** block. This is the single most credible thing on the page — not the tech stack, not the screenshots.

**Template:**

```
BEFORE                          AFTER
──────────────────────────────────────────────────────
Checkout conversion: 2.1%   →   3.4%      (+35% uplift)
Page load (LCP):    4.8s    →   2.6s      (45% faster)
Bounce rate:        68%     →   53%       (22% drop)
Manual update time: 8h/wk   →   4.8h/wk  (40% less effort)
```

**Rules:**
- Only show numbers you can defend. No invented metrics.
- If you have the before number — show it. If you only have the delta — show the delta.
- Each number must link to what you changed (not "we redesigned it", but "replaced static Liquid sections with dynamic metafields — cut content team workload by 40%").
- Where hard numbers don't exist, use qualitative before/after: "No mobile experience → Fully responsive, 60% of traffic now mobile."

### Visual Before/After — Image Slider

Where a screenshot tells the story better than numbers (redesigns, UI overhauls, visual migrations), each case study page will include a **drag-to-reveal image comparison slider**.

- Drag handle left/right reveals before / after screenshot
- Works on mouse, touch, keyboard (arrow keys)
- Labels: "Before" / "After" (or custom e.g. "Old site" / "Redesign")
- Component built: `src/components/BeforeAfterSlider.tsx`

**Usage per case study:**
```tsx
<BeforeAfterSlider
  before="/images/[project]-before.jpg"
  after="/images/[project]-after.jpg"
  beforeLabel="Old site"
  afterLabel="Redesign"
  aspect="16/9"
/>
```

**Images to gather per project:**
- Full-page screenshot of the old design (Wayback Machine or client files)
- Full-page screenshot of the live redesigned site
- Crop to the most impactful view (hero + above fold is enough)

**Projects where Before/After applies (to gather data):**
- Ponds India (Shopify performance + conversion)
- Liquid IV Australia / Canada (checkout, load time)
- Wipro Consumer Lighting (headless migration — load time delta)
- Be Beautiful (content update frequency, traffic)
- EdgeVerve (page performance, bounce rate)
- Brew For You (conversion, AOV)
- Any Langoor project with analytics access

**Where you don't have data:**
- Still show the problem statement: *"The brand had no D2C presence in India. They needed a storefront that could handle Diwali traffic spikes."* That's a before/after in words.

## UI Micro-Tweaks (Alongside Content — No Structural Change)

The overall UI is strong. These are targeted fixes where visual treatment
is actively weakening the new content — not a redesign.

### Do these:
1. **Stats strip numbers** — outcome numbers (35%, 98%) need more visual weight.
   Accent color on the number itself. Make them land harder.
2. **Work cards typography** — add hierarchy between outcome claim (larger/brighter)
   and brand name + stack (smaller/dimmer). Currently same visual weight.
3. **Hero descriptor** — "Still learning." deserves visual separation. Italic or
   dimmer color so it reads as a personal aside, not a continuation of authority statement.
4. **"Hi, I'm" greeting** — conflicts with the new authority positioning. Replace with
   a small eyebrow label in small caps, or let the name lead without a greeting.

### Leave completely alone:
- Aurora + particles hero background
- Name treatment (huge, bold — works)
- ChromaGrid layout
- Page transitions
- Dark color system
